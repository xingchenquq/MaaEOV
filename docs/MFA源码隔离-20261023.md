## 二、配置与依赖调整

### 1. `MFA_SRC` 语义变化（兼容保留）

| 用法 | 行为 |
|---|---|
| 不设 | 用 `vendor/MFAAvalonia`（新默认） |
| `MFA_SRC=<路径>` | 仍可覆盖（旧用法继续有效），用于临时试别的源码 |

### 2. 框架版本 ↔ Python 绑定必须一致（原有约束，现在有了自动提示）

`vendor` 的 `MFAAvalonia.csproj` 决定 MaaEOV GUI 内置的原生库版本。`sync_mfa_src.sh` 会直接打印：

```
MaaFw 版本 : 5.12.3
MaaEOV 的 Python 绑定必须同版本，否则代理模式会出难以定位的崩溃：
   ./python/python.exe -m pip install --no-cache-dir "maafw==5.12.3"
```

以后不用再去别处 grep 版本号。

### 3. 新增磁盘与网络依赖

- 磁盘：+96 MB（副本含完整 `.git`，可用 `--depth 1` 压到约 40 MB，但换 tag 会麻烦，不推荐）
- 网络：首次克隆优先走本地镜像，**不需要网络**；镜像不存在时才回退 GitHub
- 旧 tag：本地克隆已带上全部历史 tag；只有切到「主仓库还没有的新 tag」时才需要 `git fetch`

### 4. 不再依赖主仓库存在

这是主要收益：主仓库改名、移动、删分支、甚至删库，都不影响 MaaEOV 构建。

```bash
# 从 MaaEOV/.gitignore 删掉末两行（vendor 注释 + /vendor/）
```

再把 `SRC` 默认值改回（同方案 2）。

`vendor/MFAAvalonia` 是普通 git 仓库，可以直接 `git log` / `git blame`。**不要在里面积累未提交改动**——`sync_mfa_src.sh` 会检测到并告警，因为那会让产物不可复现。
