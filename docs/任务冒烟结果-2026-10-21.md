## 2. 唯一失败项：当期活动（内容过期，非代码缺陷）

- **现象**：`#当期活动 → 当期活动 → _NavigateHomepage → … → ~Homepage` 后 `进入活动页` 30s 识别不到，任务 FAIL。
- **原因**：`进入活动页` 靠主界面右上角 banner 的 OCR「剩余X天」定位。当前活动「临界视域」已于 **2026-10-14** 结束，主界面无 banner → OCR 无匹配 → 超时。
- **与文档不符**：`interface.json` 的 doc 写「活动结束后自动跳过」，实际是**任务报失败**。`CurrentEvent.json` 注释也写「活动结束后 OCR 无匹配则任务超时跳过」—— 超时 ≠ 跳过。
- **建议**：给 `当期活动` 加一个「banner 不存在 → 成功结束」的探测节点（识别 ROI 内无「剩余」字样时走 `_Done`），否则每期活动结束到下期配置之间该任务必红。
- **待办**：新一期活动上线后需重新截图选 banner ROI + 关卡模板（CS 系列绿幕末位字形）。

## 3. 本次发现并修复的缺陷（聚合任务）

首版「一键领取 / 活动领取」用 `[JumpBack]` 并列串子链，**实机跑出两处死循环**：

### 3.1 `[JumpBack]` 弹栈后重跑子链自身（120s 内 `DailyReward` 循环 6 次）

- 写法：`"#一键领取": { "next": ["[JumpBack]DailyReward", "[JumpBack]CountermeasureProtocol", "_Done"] }`
- 实测：`CollectWeeklyReward`（子链终点）结束后**弹回 `DailyReward` 重新跑整条子链**，`CountermeasureProtocol` 执行 0 次，120s 超时。
- 结论：**MaaFW 的 `[JumpBack]` 是"回到栈顶节点并重扫其 next"，不是"回到父节点的剩余项"**。并列串多条子链会无限重跑第一条。
- 修法：改**显式硬链接** —— 入口只指向第一条子链，各子链的「正常终止节点」直接 `next` 到下一环。

### 3.2 跳过出口改成 DoNothing 后，在导航链里自环（155 节点后超时）

- 写法：把 `_DailyStaminaBonusNAFromEvent` 从 `action: StopTask` 改成 `action: DoNothing`（希望"跳过本轮、继续下一环"）。
- 实测：`_DailyStaminaBonusNA ↔ _DailyStaminaBonusNAFromEvent` 无限交替，155 节点后超时。
- 原因：该节点位于 `[JumpBack]_DailyStaminaBonusNA` 的内层，空 `next` 会弹栈回导航父节点，父节点重扫 next 又命中它，条件永远成立。
- 结论：**MaaFW 没有跨调用层的 goto/带值返回，`StopTask` 是唯一能真正终止的出口**（且被判定为成功）。
- 修法：保留 `StopTask`，把**可能不存在的活动环排在末位**，让"跳过"等价于"收尾"。顺序：邮件 → 每日行动补给 → 短期支援补贴。

## A. 结论：默认流程不选关，直接对「游戏当前选中关卡」开扫荡

`option=危机行动调令-选择关卡` 的每个 case 只覆盖一个节点：

```json
"CrisisMissionTicketsSelectLevel": { "next": ["_NavigateS303"] }
```

但选关节点的调用点 `识别危机行动调令数.next` 是：

```
[ "~危机行动调令为零", "CrisisMissionTicketsFromLevel", "[JumpBack]CrisisMissionTicketsSelectLevel" ]
```

`CrisisMissionTicketsFromLevel` 靠 OCR 找底部「快速完成」按钮（roi [804,591,273,129]），而**关卡列表页底部也有这个按钮**。于是：

- 只要当前在危机行动界面（列表页或任意关卡详情页），`CrisisMissionTicketsFromLevel` 就命中 → 进入扫荡弹窗 → **`_NavigateSxxx` 永不执行**。
- 实测：游戏选中 **S001 混合体Ⅰ**、option 指定 **S303 乐园梦魇Ⅲ** → 任务直接对 S001 弹「快速完成 3 次」窗，节点路径中无 `_NavigateS303`。

### 反向验证：一旦真的走选关链，点击是准的

临时把选关放到快速完成之前后（override `CrisisMissionTicketsSelectLevel.next = ["_NavigateS303","CrisisMissionTicketsFromLevel"]`）：

- `_S303FromOngoingMission` 在左侧「进行中任务」列表（roi [78,89,91,587]）OCR 命中 `text="S303★"`，box=(95,633,74,26)，点击中心 ≈ **(132,646)**
- 点击后界面确实切到 **S303 乐园梦魇Ⅲ 详情页**（截图 `debug/task_runs/危机行动调令_timeout.png`）
- 说明**关卡定位与点击逻辑本身正确**，问题只在调用顺序。

## B. 同时发现两个阻塞性缺陷

### B1. `危机行动调令.png` 模板含数字「0」，调令非 0 时必然失配

- 模板图 `resource/base/image/BCR/危机行动调令.png` 是「B.R.C 图标 + 数字 0」的合成图。
- `检测危机行动调令HUD`（roi [1165,15,94,45]，thr 0.8）用它判断"是否在危机行动界面"。实测调令 = 4 时模板不命中 → 落到 next 的 `CrisisMissionTicketsSkipped` → **任务直接跳过，永远不打**。
- 这解释了首轮冒烟为何 27.5s 就走 `CrisisMissionTicketsSkipped`。
- OCR 本身没问题：同一 ROI [1210,22,30,33] 实测读到 `text='4'`，score 0.9957。

### B2. 选关链在界面切换动画期间会自环

- `_NavigateSxxx`（inverse gate）与 `~Sxxx`（terminal）用**相同 ROI + 相同 expected**。
- 实测出现 `_NavigateS303 → ~S303 → SelectLevel → _NavigateS303 → …` 循环 251 节点后超时：gate 判定"未到"（界面还在切）→ 执行 next → `~Sxxx` 判定"已到"→ terminal → 弹回 → gate 又判"未到"。
- 最终画面确实停在 S303，但任务已超时。

### D2. 三个根因（按发现顺序）

1. **不选关**：`FromLevel`（快速完成）排在选关之前，且关卡列表页底部也有「快速完成」→ 永远先命中，option 形同摆设。
2. **调令检测双故障**：`危机行动调令.png` 模板含数字 0（非 0 必失配）；且"HUD 检测"与"读数"是两个串联 OCR，第二个会在界面渲染期失败 → 一律落 `Skipped`。**中途试过 `post_delay` 反而让节点彻底不命中（8s 窗口内不再重试）**，最终改用 `pre_delay: 1500`。
3. **到站判定抖动 + 收尾无兜底**：`~Sxxx`（terminal）命中后弹回 `SelectLevel` 重扫，与 `_NavigateSxxx`（inverse gate）在界面切换期反复给出相反判定，实测 200+ 节点超时；`退出关卡详情页` 点击后已回主界面，但 next 只有 `返回主界面`，匹配不到即无 next → 任务误判失败。
