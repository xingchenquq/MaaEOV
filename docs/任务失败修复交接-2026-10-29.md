## 2. 问题一：阈限禁区卡在「选择关卡」

### 2.1 症状
每轮必现（10-26 起）。任务正常导航到关卡选择页后原地重试 30 秒失败，本周进度停在 0/480，周奖励全失。

### 2.2 根因
`_NavigateReceptionRoom` 用 `inverse: true` + 全屏 OCR「会客间」当判据。

```json
// 改前
"_NavigateReceptionRoom": {
    "recognition": { "type": "OCR",
        "param": { "roi": [0,0,1280,720], "expected": ["会客间"] } },
    "inverse": true,
    "next": ["~ReceptionRoom", ..., "[JumpBack]_ReceptionRoomFromLiminalZone", ...]
}
```

`inverse: true` 语义 = **识别不到才算成功**。但「会客间」既是目标关卡名，也是选择页卡片上的文字（实测 box `92,268,145,58`），全屏 OCR 必然命中 → 判据恒失败 → next 不执行 → 真正点卡片的 `_ReceptionRoomFromLiminalZone` 永远到不了。

日志铁证：
```
21.326  Node.NextList.Starting  name=LiminalZoneSelectLevel
21.328  Node.NextList.Failed
51.826  Node.PipelineNode.Failed  LiminalZoneSelectLevel
```
2 毫秒就失败，不是识别不准，是逻辑必然。

**更深一层**：同一个字符串「会客间」被 `~ReceptionRoom` 同时当作"已到达该关卡"的判据，两个互斥语义共用一个特征，物理上无法区分。

### 2.3 改动

| 文件 | 节点 | 改动 |
|---|---|---|
| `resource/base/pipeline/LiminalZone.json` | `~ReceptionRoom` | roi `[0,0,1280,720]`+「会客间」→ `[900,590,380,130]`+「进入探索/扫荡」 |
| 同上 | `_NavigateReceptionRoom` | 删除整个 `recognition` 与 `inverse:true`，改纯调度节点 |

改后：
```json
"_NavigateReceptionRoom": {
    "timeout": 30000,
    "next": [
        "~ReceptionRoom",                      // 已在详情页 → 结束
        "[JumpBack]_ServerMaintenance", ...
        "[JumpBack]_ReceptionRoomFromLiminalZone",  // 在选择页 → 点卡片
        ...
    ]
}
```

### 2.4 为什么用「进入探索 / 扫荡」
详情页右下角按钮实测为「**扫荡**」+「**进入探索**」；选择页同一 ROI 区域是底部页签「资源筹备 / 主线故事」。两者完全不重叠。

> ⚠️ 注意：**不是**「进行探索」。原问题说明文档 3.7 的建议写的是「进行探索」「回收物」，实测详情页没有这两个词（该 ROI 在详情页是"机制描述"文字区），照它改会改坏。详见 §7。

### 2.5 验证
MaaFramework 引擎 + 真实截图：

| 页面 | 旧判据（全屏会客间） | 新判据（右下角） |
|---|---|---|
| 选择页 | 命中 box(92,268) | **未命中** |
| 详情页 | 命中 box(68,93) | **命中 box(959,645)** |
| 个人信息页 | 未命中 | 未命中 |

## 3. 问题二：危机行动收尾卡在个人信息页

### 3.1 症状
每轮必现（10-22 起）。扫荡主流程全程成功（识别调令 2 → 设战斗次数 2 → 出发 → 结算 → 点确定），只在最后收尾导航失败，消耗 1 次调令后剩余作废，整任务判 FAILED。

### 3.2 根因
```json
// 改前
"退出关卡详情页": {
    "timeout": 30000,
    "recognition": { "type": "TemplateMatch",
        "param": { "roi": [11,2,413,84], "template": "当期活动/主界面图标.png", "threshold": 0.85 } },
    "action": "Click",
    "next": ["返回主界面", "~Homepage"]
}
```

三个问题叠加：
1. **ROI 过宽**：`[11,2,413,84]` 覆盖整个左上角 413×84，不是退出按钮的精确框
2. **模板区分度不足**：在个人信息页以 **0.543** 命中左上角返回箭头（box `103,17,48,43`）
3. **进个人信息页后无路可走**：next 两候选 `返回主界面` 0.543、`~Homepage` 0.247，都够不到 0.85 → next 为空 → 30 秒超时

## 7.5 第二轮：实机核对与修正（2026-10-29 晚，MuMu 实机）

### 7.5.1 核对方法（**原文档 §1.2 的脚本在工作区里并不存在，本次重建**）

| 脚本 | 位置 | 用途 |
|---|---|---|
| `reco.py` | `temp/verify/` | 判据 × 截图矩阵，直接调 MaaFramework 引擎跑 OCR / TemplateMatch |
